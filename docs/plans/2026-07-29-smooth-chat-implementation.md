# Smooth Chat 实施计划

## 目标

交付一个可通过 SillyTavern“安装扩展”功能安装的第三方前端扩展，实现原生聊天截断、每 15 轮增量摘要、请求期上下文裁剪、安全降级和摘要管理界面。

## 阶段一：项目骨架与设置

1. 创建 `manifest.json`、`index.js`、`settings.html`、`style.css` 和 `src/` 模块目录。
2. 定义全局默认设置和每聊天 metadata schema。
3. 在扩展面板挂载设置 UI。
4. 实现设置读取、合并、保存和基础输入校验。
5. 添加 ESLint/Node 测试所需的最小 `package.json`。

验收：

- manifest 可解析。
- 模块可由浏览器以 ES Module 方式加载。
- 模拟上下文中设置能够初始化与持久化。

## 阶段二：页面性能控制

1. 通过 `SillyTavern.getContext().powerUserSettings` 应用聊天消息加载上限，不修改快速 UI 或主题设置。
2. 记录安装前值，并避免覆盖用户后来手动修改的值。
3. 实现显式恢复按钮。
4. 仅在值实际变化时刷新聊天。

验收：

- 默认显示上限为 60 条。
- 原生“显示更多消息”仍正常工作。
- 恢复按钮可还原记录值。

## 阶段三：增量摘要状态机

1. 实现可测试的轮次识别和消息规范化。
2. 实现批次指纹和 checkpoint 状态。
3. 实现摘要提示构造与 `generateRaw()` 调用。
4. 实现单聊天串行队列、跨聊天写入保护和错误状态。
5. 监听角色回复、聊天切换、消息编辑、删除和滑动事件。
6. 实现立即总结、暂停和重建操作。

验收：

- 15 个完整轮次触发一次调用。
- 第二批摘要携带上一摘要。
- API 失败不推进 checkpoint。
- 切换聊天不会串写 metadata。

## 阶段四：请求期上下文管理

1. 在 manifest 注册全局 Prompt Interceptor。
2. 跳过 quiet/raw 和扩展禁用状态。
3. 验证 checkpoint 指纹和摘要健康状态。
4. 从临时请求数组移除安全范围内的旧消息。
5. 注入系统摘要，保留最近 6 轮和所有未总结消息。
6. 对失败、过期、重建中状态实施不裁剪降级。

验收：

- 原始聊天数组内容和长度不变。
- 有效摘要时请求历史受控。
- 无效摘要时请求保留全部历史。

## 阶段五：设置体验与状态反馈

1. 完善当前聊天状态卡。
2. 实现摘要查看/编辑弹窗。
3. 为长任务显示非阻塞状态和 toastr 提示。
4. 检测可能的内置 Summarize 冲突并只提示一次。
5. 使用 SillyTavern 主题变量完成桌面和移动端样式。

验收：

- 常用操作无需打开开发者工具。
- 设置标签、错误信息和按钮状态清晰。
- 移动端面板不横向溢出。

## 阶段六：测试、文档与打包

1. 为纯逻辑模块编写 Node 单元测试。
2. 为模拟 SillyTavern 上下文编写集成测试。
3. 执行语法检查、测试和 manifest 校验。
4. 编写中文 README、安装、升级、卸载与故障排查说明。
5. 生成可直接导入或发布到 Git 仓库的 ZIP 包。

验收：

- 自动化测试全部通过。
- README 明确说明额外 token 消耗、摘要风险和原始记录安全性。
- ZIP 根目录结构符合 SillyTavern 第三方扩展要求。
